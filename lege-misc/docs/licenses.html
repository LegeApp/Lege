OCR Components and Platform Paths

The standard build uses:

  • Linux and macOS: embedded PP-OCRv5 mobile detection and multilingual recognition models plus the PaddleOCR character dictionary. Lege parses the ONNX files and executes them through its own wgpu backend.
  • Windows: the operating system’s WinRT OCR APIs.

PaddleOCR is released under Apache-2.0. Lege’s two embedded model files are fp16 ONNX conversions of the PP-OCRv5 mobile models. Their source project is PaddlePaddle/PaddleOCR.

Tesseract remains an optional legacy compile-time backend on Linux and macOS. It is not enabled by the standard build, and standard release packages do not require a Tesseract runtime or trained-data files.

Embedded Models and Data

The standard processor embeds these assets into the executable at compile time:

  • ppocr-det.onnx — PP-OCRv5 text detection
  • ppocr-rec.onnx and ppocr-dict.txt — PP-OCRv5 text recognition
  • doclayout.onnx — document layout analysis
  • sauvola.onnx — optional heavy document binarization

Model files are copyrightable assets separate from the Rust code. The PaddleOCR provenance is identified above. Exact source revisions, conversion recipes, checksums, and redistribution terms for the layout and Sauvola models should remain part of the release audit rather than being inferred from the Rust dependencies.

Release Audit Items

Before publishing a release, keep these items with the reproducible build record:

  • source revision, conversion recipe, and checksum for every embedded model and dictionary
  • the complete Cargo dependency/license report for the exact target and enabled feature set
  • the separate djvu-encoder AGPL license notice when that executable is included
  • platform runtime libraries copied into an installer, if any
