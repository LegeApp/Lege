Lege Document Processing Application

This is a walkthrough of the features in the Lege processing application. The name is derived from the Latin, Legere.

Book Processing Ecosystem

Lege is intended to be part of a mini-ecosystem of book processing:

  1. Get the Book PDF Scan
    Obtain the full book PDF scan on your computer. Use a hardware book scanner for old books you own, or access sites like Internet Archive or Project Gutenberg. For archive.org, the Internet Archive Downloader is the best way to download the full book as a PDF if not directly available.
  2. Manage with Calibre
    Use Calibre to manage your books. Lege is intended to complement Calibre.
  3. Process with Lege
    Process your books with Lege, the output folder defaults to the input folder. Supports PDF and DJVU outputs, with an optional OCR layer. EPUB support was planned but is not offered due to severe technical difficulties, best outlined here. Future support remains possible using Epub-fxl. Rendered images in 1-bit binarized fax format provide the best compromise for PDF inputs.
  4. Send to E-ink Reader
    Transfer the processed file to your E-ink reader. The best compact E-ink reader for external books is a Kobo model, ideally used with KoReader for DJVU support, faster book loading, page turning, WebDAV support, and more.

Features

There is also a CLI in the main program folder that is quick and easy to use. Some installers make a shortcut for it, some, like the Microsoft Store version, do not.

Outputs

PDF and DJVU
PDF is offered as an output just as it is the sole input besides a folder of images if they are numbered sequentially. DJVU is the other supported format. DJVU was a much-publicized archival format in the early 2000s which ran into copyright issues and poor marketing, so it never gained wide adoption, and then Adobe essentially adopted most of its best features for the PDF 2.0 standard. But DJVU is still the superior format for this specific use; its image compression is better across the board, and its standardized encoding and decoding allow much faster loading than a standard PDF document. Definitely choose DJVU if your e-reader supports it.

Image Output Type

Dithering and Original
Dithering is the method of reducing diffusion error when reducing the color space of an image, leading to a much more natural result. When dithering is enabled, a picture is reduced from 16 million colors down to 1-bit color while preserving fine detail where possible. CCITT4 uses a custom dithering method while JBIG2 uses Stucki by default. There is also an option that uses spec-correct JBIG2 halftone regions in the CLI; the output is worse quality but the file sizes are lower.

CCITT Group 4 and JBIG2, fax formats from the 1990s, are used for text and dithered image areas. In the GUI the choice is between dithered or original image areas. JBIG2 is used if dithered is chosen and CCITT4 is used for original images by default.

Layout Detection

This is achieved with a PaddleX model. It detects 21 different layout elements on each page, but for the program’s purposes only 8 are used.

Layout detection runs through Lege’s native wgpu compute path (Vulkan or DirectX 12 on Windows/Linux and Metal on macOS) and prefers a discrete GPU when one is available. Its purpose is to identify and protect image regions from binarization, because the binarization methods will ruin picture quality so those regions must be treated separately per page. Layout detection is on by default. The best reason to turn it off is to get image areas processed by the same binarization as text for situations such as documents containing only line art.

OCR Text Layer

OCR generates the searchable text overlay, inferred metadata, and an automatic table of contents from headings found by layout analysis. Windows uses the system WinRT OCR API; Linux and macOS use the PP-OCRv5 detection and recognition models embedded in Lege and executed by its native wgpu inference engine. If your input PDF already has an OCR layer, Lege retains it when OCR is off. Enabling OCR generates a replacement layer. Fast mode runs full-page recognition for a search overlay. Thorough mode feeds individually prepared text lines to recognition at higher detail and is intended for EPUB creation or when text accuracy matters most.

Page Range

You can set the page range to process. If you set a page range, the cover image feature will be disabled automatically. Otherwise, the first page is always treated as the cover, and thus as a full-page image area.

Target Height / Width

You can set the target height of the output PDF pages in pixels. Width is set proportionately based on the original proportions of the page.

Functionality has been recently added to set the output, unproportionately, to the exact screen dimensions of specific e-ink readers. That way no fiddling is necessary to get the pages to crop or center or scale to the screen, although the text itself will appear different than the original page since its proportions have been altered.

There is no clean final way to do this, but the goal is to provide all of the practical compromises.

Margin Correction and Reflow

Margin correction is done via the bounding boxes from layout detection. Centering will equalize the margins on either side versus the dimensions of the main bounding box areas. Cropping will crop as much as possible toward those boxes while preserving aspect ratio. Footnotes will be preserved. Forced margin cropping can be set. There is also algorithmic margin detection that works when layout detection is off and produces similar results.

Reflow is new since 1.45, replacing Deskew, and is an indirect port of the Reflow feature in K2PDFOPT, an excellent program. Lege's version is slightly less effective but multiple times faster and simpler to use. It will reorganize rasterized text on a paragaph level to be larger and to span more document pages while preserving most other formatting.

Adaptive Binarization

Uses a Sauvola / Otsu fusion method, two well-known binarization techniques, which works great every time. The source is cited in the Licenses section even though it was unlicensed and free to use, because it is good enough that it deserves attribution. There is one issue where it will try to binarize blank or almost blank pages and produce static patterns. There is code to prevent this when layout mode is turned on. If there are no detections on a page, it uses a threshold at 128 for any blank page. But when layout detection is turned off and adaptive binarization is used, blank pages can still be affected this way.

Heavy model

Document binarization is an entire field, and there is a yearly international contest for the best document binarization method. In recent years the field has moved almost completely to neural models, where before it was mostly algorithms.

Lege also supports a heavier neural model that was a participant in one such contest and performs very well for historical and degraded documents. It is offered as a backup in case the lighter method creates or retains imperfections in the final output.

It is much slower, up to 3 seconds per page to process.

Log Feature

Lastly, there is a log feature in the bottom right that shows the last 20 documents processed in Lege. The log can be cleared from within the window.

Recommended Settings

Here are a few recommendations for using the program based on the input book:

  1. Old book with yellowed but undamaged pages with images with solid, simple coloring: keep layout detection off and run it with a fixed threshold between 128 and 200. The fixed threshold will affect images the least.
  2. Old book with yellowed, damaged, discolored, spotty pages: use adaptive binarization. It is designed for that kind of book. The heavy model is for when even the text is degraded.
  3. Book with gray or other color pages and full-color images: use adaptive binarization and enable layout detection so the image areas will be preserved. If the pages are gray or blue, original images tend to look better. If they are yellowed, dithering usually looks better as the entire page gets binarized with image areas dithered more naturally.

One Thing

There is a natural question here: if a book is already black and white, how do you re-encode it to a manageable size without running it through binarization? The answer is that the process of re-encoding the book is binarization. The decision still has to be made for what pixels turn white and what pixels turn black. The best option is to test different simple threshold modes starting from 180 or 200. If you want to re-encode in JPEG without affecting page color much, there is an option for it in the CLI, but file size will not be reduced as much as with the two fax-based encoding modes.
