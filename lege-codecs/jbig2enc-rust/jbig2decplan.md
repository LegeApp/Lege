# Guide: Developing a Native JBIG2 Decoder Inside `jbig2enc-rust`

## 1. Objective

Add a pure-Rust JBIG2 decoder to the existing encoder crate that:

* Decodes standalone JBIG2 files.
* Decodes PDF-embedded page streams with optional `JBIG2Globals`.
* Initially supports every stream produced by the current encoder.
* Returns packed one-bit images without expanding to one byte per pixel.
* Reuses allocations across pages.
* Supports concurrent PDF-page decoding without shared mutable state.
* Treats malformed PDF input as untrusted.
* Can later support the full T.88 feature set without replacing the initial architecture.
* Shares protocol definitions with the encoder where appropriate, but does not entangle encoder and decoder state machines.

The first target is not “all JBIG2 found in the wild.” It is:

> Decode every stream generated by this repository, validate that decoder against `jbig2dec` and Hayro, and then expand feature coverage in measured layers.

That provides a useful decoder early while avoiding a large speculative implementation.

---

# 2. Repository-specific starting position

The current repository already contains much of the information needed to build the decoder:

* The complete MQ arithmetic probability-state table.
* Arithmetic integer procedure identifiers.
* IAID encoding.
* Generic-region context generation.
* Generic refinement context generation.
* Segment-type definitions.
* Segment payload writers.
* Page, generic-region, symbol-dictionary, text-region, pattern-dictionary, and halftone parameter structures.
* MMR encoding through the `fax` dependency.
* Round-trip tests using `jbig2dec`.
* The T.88 specification text.
* A packed `u32` representation cached by `BitImage`.

This means the decoder is not starting from zero. The difficult work is to convert encoder knowledge into:

1. Checked parsing.
2. Inverse arithmetic procedures.
3. Segment dependency management.
4. Bitmap composition.
5. Decoder-specific allocation and state management.

Several existing structures should **not** be reused directly:

* `Jbig2ArithCoder` combines output state, multiple context classes, integer state, IAID state, generic contexts, and refinement contexts in one encoder-specific object.
* `BitImage` is optimized around `bitvec` and encoder-side mutation, extraction, and comparison.
* `Segment::write_into()` implements only the header forms currently needed by the encoder.
* Library internals frequently use `anyhow`, assertions, `unwrap()`, and unchecked integer conversion.
* `lib.rs` and `jbig2.rs` currently duplicate several public error and context definitions.
* Crate-wide allowances for dead code, missing documentation, and unused values would obscure decoder mistakes.

The decoder should be implemented alongside the encoder, but under stricter rules.

---

# 3. Scope the work in two products

Treat the decoder as two progressively broader products.

## Product A: self-decoder

This decoder supports the exact subset emitted by the current encoder:

* Sequential standalone organization.
* PDF embedded organization.
* Optional global symbol dictionaries.
* Page information.
* Immediate generic regions.
* Arithmetic generic coding, initially template 0.
* Direct-coded arithmetic symbol dictionaries.
* Arithmetic text regions.
* IAID symbol IDs.
* Arithmetic integer procedures.
* Per-instance generic refinement.
* Pattern dictionaries and halftone regions emitted by the current halftone encoder.
* MMR where the current encoder emits it.
* End-of-page and end-of-file segments.

This should be the first release milestone.

## Product B: general PDF decoder

This adds features encountered in arbitrary PDF files:

* Random-access organization.
* Unknown segment lengths.
* Long-form referred-to segment counts.
* Generic templates 1–3.
* Typical prediction.
* Intermediate regions.
* Striped pages.
* Huffman-coded symbol dictionaries and text regions.
* Standard and custom Huffman tables.
* Aggregate-coded dictionary symbols.
* Retained arithmetic contexts.
* Additional refinement arrangements.
* More unusual segment-reference graphs.
* Compatibility recovery for malformed files.

Do not block Product A on Product B.

# 5. Clean the public API before implementation

Consolidate the duplicated `Jbig2Error`, `Jbig2Context`, and related exports currently present in `lib.rs` and `jbig2.rs`.

Use separate typed errors:

```rust
#[derive(Debug, thiserror::Error)]
pub enum DecodeError {
    #[error("invalid JBIG2 file header")]
    InvalidFileHeader,

    #[error("unexpected end of input at byte {offset}")]
    UnexpectedEof {
        offset: usize,
    },

    #[error("invalid segment {segment}: {source}")]
    Segment {
        segment: u32,
        #[source]
        source: SegmentDecodeError,
    },

    #[error("decode limit exceeded: {0}")]
    Limit(#[from] LimitError),

    #[error("integer overflow while decoding {operation}")]
    Overflow {
        operation: &'static str,
    },

    #[error("unsupported JBIG2 feature: {0}")]
    Unsupported(UnsupportedFeature),
}
```

Use `anyhow` only in binaries and test utilities. Decoder library code should return structured errors.

The initial public API should be small:

```rust
pub fn decode_file(
    data: &[u8],
    options: &DecodeOptions,
) -> Result<DecodedDocument, DecodeError>;

pub fn decode_embedded(
    globals: Option<&[u8]>,
    page_data: &[u8],
    options: &DecodeOptions,
) -> Result<MonoBitmap, DecodeError>;

pub fn decode_embedded_with_context(
    globals: Option<&DecodedGlobals>,
    page_data: &[u8],
    options: &DecodeOptions,
    context: &mut DecoderContext,
) -> Result<MonoBitmap, DecodeError>;
```

For integration with the PDF renderer, add an output-oriented variant later:

```rust
pub fn decode_embedded_into(
    globals: Option<&DecodedGlobals>,
    page_data: &[u8],
    destination: &mut MonoBitmap,
    options: &DecodeOptions,
    context: &mut DecoderContext,
) -> Result<(), DecodeError>;
```

This avoids an extra bitmap allocation when the PDF image pipeline already owns the destination.

# 6. Make globals independently reusable

PDF `JBIG2Globals` commonly contain symbol dictionaries shared by multiple page streams. Parse and decode them once:

```rust
pub struct DecodedGlobals {
    segments: SegmentStore,
    symbol_dictionaries: Vec<Arc<SymbolDictionary>>,
    pattern_dictionaries: Vec<Arc<PatternDictionary>>,
}
```

Requirements:

* `DecodedGlobals: Send + Sync`
* No mutex required for ordinary access
* No worker scratch stored inside it
* All decoded global resources immutable
* Page workers receive `&DecodedGlobals`
* Page-local arithmetic and bitmap scratch stays in `DecoderContext`

The intended PDF execution model becomes:

```text
PDF JBIG2Globals bytes
        ↓ once
DecodedGlobals
        ↓ shared immutably
 ┌──────┼────────┬────────┐
page 1  page 2   page 3   page 4
ctx 1   ctx 2    ctx 3    ctx 4
```

This is more important to whole-document performance than parallelizing one JBIG2 page internally.

# 7. Introduce a decoder-native packed bitmap

Do not use one byte per pixel internally.

Do not make `bitvec` indexing the decoder’s primary pixel path.

Use a row-padded packed representation:

```rust
#[derive(Clone, PartialEq, Eq)]
pub struct MonoBitmap {
    width: u32,
    height: u32,
    stride_words: u32,
    words: Vec<u32>,
}
```

Maintain the current encoder convention:

* Most-significant bit is the leftmost pixel.
* Set bit means black.
* Each row starts on a `u32` boundary.
* Padding bits at the end of a row are zeroed.

Essential methods:

```rust
impl MonoBitmap {
    pub fn new(
        width: u32,
        height: u32,
        fill_black: bool,
        limits: &DecodeLimits,
    ) -> Result<Self, DecodeError>;

    pub fn row(&self, y: u32) -> &[u32];

    pub fn row_mut(&mut self, y: u32) -> &mut [u32];

    pub fn get(&self, x: u32, y: u32) -> bool;

    pub fn set(&mut self, x: u32, y: u32, black: bool);

    pub fn combine(
        &mut self,
        source: &MonoBitmap,
        x: i32,
        y: i32,
        operator: CombinationOperator,
    );

    pub fn as_msb_bytes(&self) -> PackedRows<'_>;
}
```

Combination operators:

```rust
pub enum CombinationOperator {
    Or,
    And,
    Xor,
    Xnor,
    Replace,
}
```

`combine()` must:

* Clip signed destination coordinates.
* Handle non-word-aligned source placement.
* Operate on whole words where possible.
* Handle first and last partial words with masks.
* Avoid per-pixel loops for the central span.
* Keep source and destination aliasing rules explicit.

This layout is already suitable for later SIMD without requiring SIMD in the first decoder.

Initially provide conversions between `MonoBitmap` and the existing `BitImage`. Migrate encoder internals only after the decoder is stable.

# 8. Build a checked slice reader

The decoder primarily consumes PDF stream bytes already held in memory. Start with a borrowed slice reader rather than a generic `Read` implementation:

```rust
#[derive(Clone)]
pub struct Reader<'a> {
    input: &'a [u8],
    offset: usize,
}
```

Methods should include:

```rust
fn position(&self) -> usize;
fn remaining(&self) -> usize;
fn read_u8(&mut self) -> Result<u8, ParseError>;
fn read_i8(&mut self) -> Result<i8, ParseError>;
fn read_u16_be(&mut self) -> Result<u16, ParseError>;
fn read_u32_be(&mut self) -> Result<u32, ParseError>;
fn read_i32_be(&mut self) -> Result<i32, ParseError>;
fn take(&mut self, len: usize) -> Result<&'a [u8], ParseError>;
fn subreader(&mut self, len: usize) -> Result<Reader<'a>, ParseError>;
```

All offset and length arithmetic must use `checked_add`, `checked_mul`, and checked integer conversions.

Do not reuse the current `u32_to_usize()` helper for decoding. It is an unchecked cast despite its comment. Decoder conversions should be fallible:

```rust
fn usize_from_u32(value: u32) -> Result<usize, DecodeError> {
    usize::try_from(value).map_err(|_| DecodeError::Overflow {
        operation: "converting u32 dimension to usize",
    })
}
```

# 9. Parse first, decode second

Separate structural parsing from segment execution.

```rust
pub struct ParsedSegment<'a> {
    pub header: SegmentHeader,
    pub data: &'a [u8],
}
```

```rust
pub struct ParsedDocument<'a> {
    pub organization: FileOrganization,
    pub segments: Vec<ParsedSegment<'a>>,
}
```

This permits:

* Validation before allocating page bitmaps.
* Random-access organization later.
* Segment-number indexing.
* Dependency resolution.
* Better errors.
* Fuzzing parsing without invoking image decoding.
* Reusing parsed globals.

Do not decode payloads while the file parser is still trying to identify where segment data begins.

## Segment header parser requirements

Implement the full T.88 header syntax even if the initial encoder does not emit all forms:

* Short referred-to count form.
* Long referred-to count form.
* Expanded retention flags.
* One-, two-, and four-byte referred segment numbers.
* One- and four-byte page association.
* Unknown segment data length.
* Deferred non-retain flag.
* Segment-number boundaries.

Do not implement the parser as the inverse of the current `Segment::write_into()` alone. That writer intentionally rejects more than four references and does not cover every decoder case.

Also add boundary tests for:

* Segment 255
* Segment 256
* Segment 65,535
* Segment 65,536

The specification’s referred-segment-number width changes at these boundaries. The current writer’s strict `< 256` and `< 65_536` decisions should be audited separately rather than copied into the parser.

# 10. Separate MQ state from encoder and decoder machines

The probability table is shared protocol data. The arithmetic registers are not.

Create:

```rust
#[repr(transparent)]
#[derive(Clone, Copy, Default, PartialEq, Eq)]
pub struct MqContext(u8);
```

```rust
pub struct MqEntry {
    pub qe: u16,
    pub next_mps: u8,
    pub next_lps: u8,
}
```

Your existing 94-entry state representation can be retained:

* States `0..47`: MPS is zero.
* States `47..94`: MPS is one.
* The next-state table already incorporates switching.

Move it into `arithmetic/state.rs`.

Then implement independent types:

```rust
pub struct ArithmeticEncoder {
    // Existing encoder registers and output.
}

pub struct ArithmeticDecoder<'a> {
    input: &'a [u8],
    offset: usize,
    a: u32,
    c: u32,
    ct: u8,
    previous_byte: u8,
}
```

The decoder’s central API should update one context directly:

```rust
impl ArithmeticDecoder<'_> {
    #[inline(always)]
    pub fn decode_bit(
        &mut self,
        context: &mut MqContext,
    ) -> Result<bool, ArithmeticError>;
}
```

Do not make `ArithmeticDecoder` own a universal 65,536-entry context array. The region or integer procedure owns the relevant contexts.

This produces clearer state lifetimes:

```rust
let mut contexts = GenericContexts::for_template(header.template);
let mut decoder = ArithmeticDecoder::new(payload)?;
let bit = decoder.decode_bit(&mut contexts[index])?;
```

# 11. Extract arithmetic integer and IAID procedures

The current encoder already contains the integer ranges, context update rule, `IntProc`, and IAID tree behavior.

Move the shared definitions into `arithmetic/integer.rs`, but keep the encoding and decoding procedures separate.

Use a typed result for arithmetic integers:

```rust
pub enum DecodedInteger {
    Value(i32),
    OutOfBand,
}
```

API:

```rust
pub struct IntegerContexts {
    procedures: [[MqContext; 512]; 13],

impl IntegerContexts {
    pub fn decode(
        &mut self,
        decoder: &mut ArithmeticDecoder<'_>,
        procedure: IntProc,

```

IAID:

```rust
pub struct IaidContexts {
    states: Vec<MqContext>,

impl IaidContexts {
    pub fn reset_for_bits(&mut self, bits: u8) -> Result<(), DecodeError>;

    pub fn decode(
```

The context vector should be reused through `DecoderContext`, not allocated for every text region.

# 12. Implement decoder limits before decoding images

JBIG2 input comes from untrusted PDF files. Limits are part of the decoder architecture, not later hardening.

```rust
pub struct DecodeLimits {
    pub max_width: u32,
    pub max_height: u32,
    pub max_page_pixels: u64,
    pub max_region_pixels: u64,
    pub max_segments: usize,
    pub max_referred_segments: usize,
    pub max_symbols: usize,
    pub max_symbol_pixels: u64,
    pub max_total_dictionary_pixels: u64,
    pub max_dependency_depth: usize,
    pub max_retained_bytes: usize,
    pub max_huffman_table_entries: usize,
}
```

Check limits before every allocation.

Decoder code should contain no input-reachable:

* `assert!`
* `debug_assert!` relied upon for safety
* `unwrap()`
* `expect()`
* unchecked multiplication
* unchecked dimension conversion
* indexing based directly on encoded values

A malformed stream must return an error, not panic or attempt a multi-gigabyte allocation.

# 13. Decoder context and allocation reuse

Use:

```rust
#[derive(Default)]
pub struct DecoderContext {
    pub arithmetic_contexts: Vec<MqContext>,
    pub integer_contexts: IntegerContexts,
    pub iaid_contexts: IaidContexts,

    pub previous_row: Vec<u32>,
    pub current_row: Vec<u32>,

    pub temporary_bitmap: MonoBitmap,
    pub refinement_bitmap: MonoBitmap,

    pub symbol_scratch: Vec<Arc<MonoBitmap>>,
    pub referred_segment_scratch: Vec<u32>,
}
```

The context belongs to one worker and can be reused for many pages.

Hayro’s decoder follows the same broad pattern: its reusable `DecoderContext` owns page state, a page bitmap, and scratch buffers, and its public API allows repeated images to reuse those allocations.
Do not put `DecoderContext` behind a mutex. The PDF renderer should allocate one context per decoding worker.

After a pathological page, trim buffers that exceed a configured retained-capacity threshold so one malicious page does not permanently inflate every worker.

# 14. First functional path: generic regions

Implement generic-region decoding before symbol dictionaries.

## First supported form

Match the encoder’s ordinary output:

* Arithmetic coding.
* Template 0.
* Four adaptive-template coordinates.
* No skip bitmap.
* Typical prediction disabled in the normal encoder configuration.
* Immediate region composition.
* Known segment length.

The decoder reconstructs each pixel from:

* Previously decoded rows.
* Previously decoded pixels in the current row.
* Adaptive-template positions.
* One MQ context selected from those pixels.

Use the same context geometry as the encoder, but do not call an encoder helper that reads the target image. The decoder must build the context from already reconstructed pixels.

## Efficient scalar implementation

Use:

* Two prior packed rows.
* One current packed row.
* Sliding context registers.
* A direct write into the destination row.
* Specialized handling for left and right edges.
* No `get(x, y)` function call for every context sample.

The current encoder’s `c1`, `c2`, and `c3` rolling context structure is a useful model. The decoder should mirror that rolling organization while inserting the just-decoded pixel into `c3`.

## Expansion order

After template 0:

1. Templates 1–3.
2. Typical prediction generic decoding.
3. Skip bitmap.
4. Unknown arithmetic payload length.
5. MMR generic regions.

The existing `fax` crate provides Group 4 decoding support, so it is economical to use its decoder behind a small internal wrapper initially rather than writing a second T.6 implementation immediately.

```rust
trait MmrDecoder {
    fn decode_into(
        &mut self,
        data: &[u8],
        width: u32,
        height: u32,
        output: &mut MonoBitmap,
    ) -> Result<(), MmrError>;
}
```

This wrapper makes replacement possible if the dependency later proves unsuitable.

# 15. Page state and direct region composition

Represent page decoding explicitly:

```rust
pub struct PageState {
    pub info: PageInformation,
    pub bitmap: MonoBitmap,

    regions: SegmentMap<MonoBitmap>,
    symbol_dictionaries: SegmentMap<Arc<SymbolDictionary>>,
    pattern_dictionaries: SegmentMap<Arc<PatternDictionary>>,
    huffman_tables: SegmentMap<Arc<HuffmanTable>>,
}
```

Immediate regions should normally decode directly into the page bitmap when:

* The region is fully inside the page.
* The region operation is compatible.
* No later use requires retaining the standalone region.
* The initial region value matches the destination assumptions.

Otherwise:

1. Decode into a temporary bitmap.
2. Combine with the page.
3. Retain only if referenced later.

Hayro similarly distinguishes cases that can decode directly into the page bitmap from those that require a temporary region followed by composition.

This is worth implementing early because scanned pages frequently contain one page-sized immediate generic region.

# 16. Symbol dictionary decoding

The current encoder’s default dictionary path is substantially simpler than the complete specification:

* Arithmetic coding.
* Template 0.
* No Huffman coding.
* `SDREFAGG` false for the ordinary dictionary encoder.
* Symbols sorted by height, then width.
* Direct-coded symbol bitmaps.
* Exported symbols selected after decoding.

Implement that subset first.

## Decoder representation

```rust
pub struct SymbolDictionary {
    pub exported_symbols: Box<[Arc<MonoBitmap>]>,
    pub retained_contexts: Option<RetainedArithmeticContexts>,
}
```

Use `Arc<MonoBitmap>` because:

* Text regions refer to symbols without copying.
* Global dictionaries are shared across page workers.
* Re-exported symbols can point to existing symbol bitmaps.
* Imported and new symbols can coexist in one logical symbol list.

## Self-decoder sequence

1. Gather exported symbols from referred dictionaries.
2. Parse dictionary flags and AT coordinates.
3. Read `SDNUMEXSYMS` and `SDNUMNEWSYMS`.
4. Decode height-class delta.
5. Decode width deltas.
6. Decode each direct symbol bitmap.
7. Decode exported-symbol run lengths.
8. Publish only exported symbols.

Use checked accounting:

```text
imported symbols
+ new symbols
= complete dictionary symbol space

export run lengths
must exactly cover complete symbol space
```

Any overrun, underrun, or impossible count is an error.

## Later expansion

Add in this order:

1. Collective bitmap decoding.
2. Single-reference refinement symbols.
3. Aggregate symbols with multiple instances.
4. Huffman-coded dictionaries.
5. Context retention and reuse.
6. User-supplied Huffman tables.

# 17. Text-region decoding

Once arithmetic integer decoding, IAID, and basic symbol dictionaries work, the current text-region encoder can be inverted directly.

The decoder should:

1. Gather exported symbols from referred dictionaries in reference order.
2. Calculate symbol-ID bit width.
3. Parse text-region flags.
4. Decode the initial `IADT`.
5. Decode strips.
6. Decode `IAFS` for the first symbol in a strip.
7. Decode repeated `IADS` until OOB.
8. Decode `IAIT` where strip height requires it.
9. Decode IAID symbol ID.
10. Optionally decode refinement parameters.
11. Combine the symbol bitmap into the region bitmap.
12. Continue until `SBNUMINSTANCES` symbols have been placed.

Use a placement structure only for debugging. Production decoding should combine each symbol as it is decoded rather than storing all instances first.

## Important validation

Check:

* Symbol ID is within the referred dictionary set.
* Instance count does not exceed declared count.
* Coordinates do not overflow.
* Strip calculations do not overflow.
* Refinement dimensions remain within limits.
* OOB occurs only where permitted.
* Declared instance count is reached exactly.

## Refinement

Your encoder can retain per-instance refinement in PDF mode. Therefore refinement decoding is part of the self-decoder, not a distant compatibility feature.

Implement:

```rust
fn decode_refined_symbol(
    decoder: &mut ArithmeticDecoder<'_>,
    reference: &MonoBitmap,
    width: u32,
    height: u32,
    dx: i32,
    dy: i32,
    template: RefinementTemplate,
    contexts: &mut RefinementContexts,
    output: &mut MonoBitmap,
) -> Result<(), DecodeError>;
```

The encoder already documents the intended 13-bit template-0 context. Convert that documentation into shared template constants and independent encoder/decoder tests.

Do not share one mutable refinement-context array across page workers. Reset or retain it only according to segment semantics.

# 18. Pattern dictionaries and halftone regions

Implement these after generic, dictionary, and text paths.

The current halftone configuration defaults to:

* MMR for the collective pattern dictionary.
* Arithmetic or MMR gray planes depending on configuration.
* A normal pattern dictionary segment.
* A page-local halftone region.

## Pattern dictionary

1. Parse MMR and template flags.
2. Read pattern width, height, and `GRAYMAX`.
3. Decode one collective bitmap sized:

```text
(pattern count × pattern width) × pattern height
```

4. Split it into individual immutable pattern bitmaps.

The pattern count is `GRAYMAX + 1`; check overflow before multiplication.

## Halftone region

1. Resolve the referred pattern dictionary.
2. Decode gray-code bitplanes.
3. Convert gray code to binary indices.
4. Calculate each grid location using fixed-point arithmetic.
5. Retrieve the pattern.
6. Combine it into the halftone region bitmap.
7. Combine the completed region into the page.

Use signed 64-bit intermediates for grid calculations. Validate before narrowing to page coordinates.

# 19. Segment storage and dependencies

Do not use a single untyped `HashMap<u32, Box<dyn Any>>`.

Use typed stores or an enum:

```rust
pub enum DecodedSegment {
    SymbolDictionary(Arc<SymbolDictionary>),
    PatternDictionary(Arc<PatternDictionary>),
    Region(Arc<MonoBitmap>),
    HuffmanTable(Arc<HuffmanTable>),
    Metadata,
}
```

```rust
pub struct SegmentStore {
    values: FxHashMap<u32, DecodedSegment>,
}
```

The decoder should process page-affecting segments in stream order, while resolving explicitly referred resources by segment number.

For the initial sequential and embedded organizations, referred segments should already be available. Later random-access support can parse all headers first and assign payload slices before executing in logical order.

Retention flags may initially be parsed and validated without immediately freeing unretained resources. Implement reclamation after correctness is stable. Limits still bound worst-case retained memory.

# 20. Strictness and compatibility modes

Use:

```rust
pub enum DecodeStrictness {
    Strict,
    Compatible,
}
```

`Strict`:

* Enforces reserved bits.
* Rejects inconsistent counts.
* Rejects unsupported flag combinations.
* Requires exact payload consumption where defined.
* Is used by encoder round-trip tests.

`Compatible`:

* Permits documented recovery for malformed PDFs.
* Records recovery events.
* Never silently invents large dimensions or counts.
* Is used by the PDF renderer after recoveries are tested.

```rust
pub enum RecoveryEvent {
    IgnoredReservedBits {
        segment: u32,
    },
    TruncatedExportRuns {
        segment: u32,
    },
    IgnoredTrailingData {
        segment: u32,
        bytes: usize,
    },
}
```

Do not begin with broad permissiveness. Every compatibility recovery should be tied to a real corpus case.

# 21. Testing strategy

## 21.1 Arithmetic unit tests

Use three levels.

### State-transition tests

For every MQ state:

* Decode MPS.
* Decode LPS.
* Verify next context state.
* Verify switch behavior.

### Encoder-to-decoder decision tests

In test code:

1. Generate a deterministic sequence of context IDs and bits.
2. Encode it with `ArithmeticEncoder`.
3. Decode it with `ArithmeticDecoder`.
4. Assert every bit.
5. Assert final context states.

Test:

* Long MPS runs.
* Long LPS-heavy sequences.
* Byte stuffing around `0xFF`.
* Termination markers.
* Truncated streams.

### Specification examples

Add the official arithmetic-decoder examples and Annex H files as permanent fixtures.

## 21.2 Generic-region property tests

# 22. Performance architecture

Do not optimize the arithmetic loop before the decoder is correct, but avoid architectural barriers.

## Keep hot data contiguous

* `MqContext` is one byte.
* Context arrays are dense vectors or fixed arrays.
* Bitmap rows are packed `u32` slices.
* Symbols are held in dense slices.
* Segment references are converted to resolved indexes before pixel decoding where practical.
* No hash lookup occurs per pixel or per symbol bit.

## Reuse allocation

* Context arrays belong to `DecoderContext`.
* Temporary region bitmaps reuse capacity.
* IAID contexts resize only when symbol-ID width grows.
* Integer contexts reset with `fill()`.
* Generic decoding writes directly to the page when safe.
* Text symbols are combined as decoded instead of stored as a full placement list.

## Avoid abstraction in bit loops

Traits are useful at boundaries, but `decode_bit()` and generic-region pixel reconstruction should be monomorphic, inlinable functions.

Do not use:

* Iterator chains in arithmetic renormalization.
* Trait objects per decoded pixel.
* `BitVec::get()` in region hot loops.
* `HashMap` for arithmetic contexts.
* A callback per decoded bit.

## Preserve future SIMD paths

SIMD will eventually be useful for:

* Bitmap combination.
* Filling rows.
* Masking partial words.
* Gray-code plane conversion.
* Pattern placement.
* Comparing or clearing packed rows.

It is less useful for the serial MQ arithmetic decision loop.

The packed `u32` bitmap representation makes those future operations straightforward without writing SIMD now.

# 24. Definition of completion for the first native decoder

The initial decoder is ready to replace Hayro in the renderer when:

1. It decodes all streams emitted by every current encoder mode.
2. It accepts standalone and PDF-embedded organizations.
3. It accepts optional shared globals.
4. Global dictionaries can be decoded once and shared across page workers.
5. Output is packed one bit per pixel.
6. Generic regions can decode directly into the page where safe.
7. All allocations are checked against explicit limits.
8. No malformed-input path can panic.
9. Local output matches `jbig2dec` and Hayro on the encoder corpus.
10. Multi-page decoding is deterministic across worker counts.
11. Decoder contexts can be reused without retaining unbounded memory.
12. The PDF renderer receives `Mono1` output without an unpack-and-repack cycle.

# 25. Central architectural rules

The implementation should adhere to these rules:

```text
Shared:
    segment syntax
    MQ probability table
    arithmetic procedure identifiers
    packed bitmap conventions
    combination operators

Separate:
    encoder registers
    decoder registers
    encoder context ownership
    decoder context ownership
    segment writing
    segment execution
```

And:

```text
Decoded globals are immutable and shared.

Decoder scratch is mutable and worker-local.

Page bitmaps are packed and destination-oriented.

Parsing never allocates from unvalidated dimensions.

The self-decoder ships before the full standard decoder.
```

That approach extracts maximum value from the existing encoder while avoiding the two common failures of codec development: duplicating protocol logic unnecessarily and trying to implement the entire standard before producing a useful result.
